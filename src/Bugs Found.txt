SMARTLOCKER STORAGE - SOFTWARE ISSUE STATUS
==========================================
Legend: '-' unresolved; '+' fixed in firmware and/or documented.

Software
--------
+ Slot unlock timers are serviced before/after main-loop work and during
  known long waits, CSV reads, and USB-copy loops. Delays from individual
  hardware/library calls still require physical timing verification.
+ Borrow and return state changes require a verified daily transaction write.
+ Serial diagnostics redact PIN input, typed text, borrower names, QR contents
  and codes, RFID UIDs, and fingerprint template IDs.
+ CSV readers assemble complete quoted records, including embedded line
  breaks.
+ New QR borrow records persist the scanned TUP code in the SD transaction
  row, and USB transaction export writes DATE, Borrower NAME, KEY NAME,
  ACTION, TIME, TUP CODE, and USER Registered columns. Borrow and return
  events are exported as separate action rows. Legacy/manual/return rows
  without a code export an empty TUP CODE field. The transaction header is
  read back from USB before export success is reported.
+ Borrow/return slot outputs remain open until a dashboard confirmation. The
  transaction is committed only after confirmation; cancel and safety-switch
  handling close the pending slot without recording the action.

Prototype verification
----------------------
Code fixes above require physical testing on the locker hardware. In
particular, measure relock timing during SD/USB activity and verify that
quoted multiline fields survive write, reload, and archive migration. Verify
TUP-code storage and transaction export on a USB drive.
Verify borrow/return confirmation popup, delayed transaction commit, cancel,
and active-high safety-switch behavior on the prototype.
